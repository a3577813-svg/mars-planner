# Журнал проектных решений

## 2026-08-05 — Планёрка остаётся самостоятельным модулем

**Решение:** сейчас разрабатывается только модуль цифровой планёрки, а не вся образовательная платформа.

**Причина:** сохранить фокус и довести основной пользовательский сценарий до устойчивого состояния.

## 2026-08-05 — Добавлена роль методиста

**Решение:** методист получает отдельный кабинет и ограниченный обзор без права изменять ответы учащихся.

**Причина:** методическое сопровождение отличается от тьюторского и административного управления.

## 2026-08-05 — Администратор назначает существующие развороты

**Решение:** вместо универсального конструктора администратор назначает конкретные развороты на конкретные недели и редактирует их содержание.

**Причина:** макет планёрки уже определён; повседневная задача — управлять временем, доступом и формулировками, а не собирать новые страницы с нуля.

## 2026-08-05 — Безопасность выделена в отдельный этап

**Решение:** защищённая серверная инфраструктура реализуется после функционального MVP, но до пилота с реальными учениками.

**Причина:** интерфейсы можно проектировать на демонстрационных данных, однако реальная эксплуатация невозможна без авторизации, серверных прав и закрытого хранения файлов.

## 2026-08-05 — Единый слой хранения

**Решение:** интерфейсы постепенно перестают обращаться напрямую к localStorage и используют общий сервис данных.

**Причина:** позже локальное хранение можно заменить API и серверной базой без полной переделки экранов.

## 2026-08-05 — Документация хранится рядом с кодом

**Решение:** техническая документация ведётся в папке `docs` в формате Markdown; рабочие содержательные версии в дальнейшем могут дублироваться в Google Drive.

**Причина:** история решений должна версионироваться вместе с проектом.
